# 「循迹」用户研究包

## 1. 目的、范围与证据状态

本研究用于验证「循迹」是否真正帮助用户理解“现在该采取什么行动”，而不是验证诊断能力。当前用户画像、任务和信任假设均来自产品设计判断；尚未完成用户访谈、可用性测试或满意度收集。

不应把本文件中的问题、招募条件或空白模板写成研究发现。访谈也不用于替代临床安全审查：产品当前离线红旗召回率为 92%（46/50），低于预设 98% 安全门槛，不能让受访者把原型当作实际医疗建议。

## 2. 探索性画像与待验证假设

### 画像（假设）

20–35 岁、习惯通过手机搜索健康信息的城市职场人。其可能在工作或通勤间隙出现不适，时间有限、医学知识有限，对相互矛盾的搜索结果感到焦虑。

### 需回答的问题

1. 用户最近一次不适时，真正需要完成的行动决策是什么？
2. 用户如何从搜索、问 AI 或问身边人转向人工医疗渠道？
3. 哪些追问能被理解为必要，哪些会造成负担或焦虑？
4. 用户能否复述结果中的时间、地点、行动与升级条件？
5. 用户在哪些条件下信任、暂停使用或转向人工？
6. 用户如何看待匿名会话、原始文本短时留存和清除记录？

### 假设清单

| 编号 | 假设 | 访谈中的可观察信号 |
| --- | --- | --- |
| H1 | 用户更需要明确行动，而非疾病名称。 | 能否自发描述“何时、去哪、做什么”的需求。 |
| H2 | 说明提问理由能降低追问阻力。 | 对问题理由的理解、跳过意愿与负担反馈。 |
| H3 | 明确未知项和升级条件会提高结果可执行性。 | 复述任务是否包含未知和升级条件。 |
| H4 | 用户愿意在高风险或信息不足时转人工。 | 何时停止在线查询、选择何种线下/人工渠道。 |
| H5 | 隐私说明和清除入口影响是否愿意输入症状。 | 对匿名、保留时长、清除按钮的理解与担忧。 |

## 3. 招募与伦理边界

- 计划招募 3–5 名符合探索性画像的成年人，覆盖不同的近期症状决策经历和 AI 使用习惯。
- 不招募正处于急症、危机或需要立即医疗帮助的人；访谈不是医疗咨询。
- 开场说明：原型不提供诊断或治疗建议；如受访者在访谈中出现紧急健康或自伤风险，应停止研究并引导其使用当地紧急/专业支持渠道。
- 不收集姓名、联系方式、病历、检查单、精确地址或可识别健康信息。记录时用参与者编号，不录入原始敏感文本。
- 取得录音/笔记单独同意；拒绝录音不影响参与。仅保留完成研究所需的最少材料，并说明删除安排。
- 研究者不评价受访者的就医选择，也不解释症状可能的疾病原因。

## 4. 30 分钟半结构化访谈提纲

### 0–3 分钟：开场与同意

1. 说明研究目的：理解健康信息决策过程，不提供医疗建议。
2. 说明可跳过任何问题、随时停止，不需要分享可识别或敏感细节。
3. 询问是否同意记笔记；如计划录音，单独确认同意。

### 3–8 分钟：最近一次症状决策经历

1. 回忆一次最近让你犹豫“要不要就医”的不适经历。可以只说你愿意分享的程度。
2. 当时最想弄清楚的是什么：严重程度、就医时机、科室、准备事项，还是其他？
3. 最终采取了什么行动？是什么信息或事件推动了这个决定？

追问：当时有哪些信息缺失？什么让你更焦虑或更安心？

### 8–13 分钟：搜索与决策路径

1. 你通常会先搜索、问 AI、问朋友/家人，还是直接联系医疗机构？为什么？
2. 看过的信息中，哪些内容有帮助，哪些让你更难决定？
3. 你何时会停止在线搜索并转向人工医疗帮助？

追问：是否曾因信息过多、表达困难或时间成本而延迟行动？

### 13–18 分钟：AI 信任与边界

1. 假设一个工具只给行动分层，不给疾病名称，你会期待它做到什么？
2. 哪些提示会让你觉得它可信？哪些说法会让你不愿使用？
3. 你如何理解“不是诊断或治疗建议”？你认为它仍然可以、又不可以做什么？
4. 哪些情况你会立即转人工，而不再继续和工具互动？

### 18–24 分钟：原型任务与复述

展示原型前再次说明：这是演示，不应用于真实健康决策。选择虚构、低风险任务卡，不使用受访者自身症状。

1. 请按你的习惯完成一次虚构任务：输入主诉、回答追问、阅读结果。
2. 每个问题出现时，你觉得它为什么被问到？是否太多、太早或不相关？
3. 阅读结果后，请用自己的话复述：你接下来何时做什么、可能去哪里、出现什么情况要升级行动？
4. 结果中的已知、未知与免责声明是否清楚？

记录观察：完成与否、停顿点、跳过/修改输入、误解、复述完整性；不要把研究者的推测当作受访者原话。

### 24–28 分钟：隐私与结果页

1. 你愿意在这类工具中输入到什么程度？哪些内容绝不愿输入？
2. “匿名会话、约 30 分钟后过期、可清除当前记录”的说明是否容易理解？
3. 你会使用就诊参考摘要吗？希望它包含或避免包含什么？
4. 复制摘要、反馈和清除记录的位置是否符合你的预期？

### 28–30 分钟：收尾

1. 如果只能改一件事，最应该改什么？
2. 是否有我们没问到、但会影响你是否使用的内容？
3. 重申原型边界，感谢参与；按同意安排处理研究材料。

## 5. 任务卡与复述判定

### 建议任务卡

使用虚构、非急症、信息完整的场景；避免让受访者以为系统正在处理其本人健康状况。例如：

> 虚构情境：某人从昨晚开始轻微咳嗽和流鼻涕，体温正常，今天比昨天好一些，没有慢性病或其他特殊风险。请使用原型整理他现在应采取的行动。

如系统在演示中出现紧急状态，停止将该结果解释为医疗建议，只记录界面与理解问题；不要求受访者照做。

### 复述记录框架

| 要素 | 记录方式 |
| --- | --- |
| 何时 | 受访者是否说出时间窗口及其含义。 |
| 去哪 | 是否理解“急救/人工渠道/门诊”等行动去向；不要求医学正确性判断。 |
| 做什么 | 是否复述立即动作、观察或准备事项。 |
| 何时升级 | 是否提及症状加重或结果中的升级条件。 |
| 边界 | 是否理解该工具不提供诊断或治疗建议。 |

## 8. 分析与下一步

当前没有访谈结果，因此不报告满意度、完成率、信任度或可用性通过率。完成首轮访谈后，优先整理：

1. 用户是否能正确复述行动、时限和升级条件；
2. 哪个追问最难理解或最容易引发不必要披露；
3. 哪些隐私说明和清除机制没有被理解；
4. 哪些误解必须通过文案、交互或安全边界修复；
5. 是否需要扩大样本、开展任务测试或邀请合格临床人员审查相关风险表达。

研究发现不能抵消离线安全门槛未通过的事实。涉及红旗、行动等级或医疗边界的改变，必须先更新合成回归案例并运行完整安全评测。
