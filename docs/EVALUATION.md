# 离线评测说明

## 结论

数据集版本 `1.1.0` 的复核轮确定性离线评测结果为：

| 指标 | 实际结果 |
| --- | ---: |
| 红旗召回率 | 92.00%（46/50） |
| 行动等级准确率 | 90.00%（108/120） |
| 边界措辞通过率 | 90.00%（108/120） |
| 平均提供轮数 | 1.32 |
| 失败案例 | 12 |

红旗召回率低于项目预先声明的 98% 安全门槛，因此当前结论是：**安全门槛未通过**。这套评测不能证明系统可上线，也不能证明临床有效。

除红旗召回率的 98% 产品安全门槛外，本项目尚未为行动等级准确率、边界措辞通过率或平均轮数批准发布门槛。本页只如实报告实际结果，不把未定义的门槛补写为“通过”。

## 数据来源与版本

`data/eval_cases.jsonl` 包含 120 条完全合成的中文产品测试案例。案例由固定红旗规则、状态机可接受的信息槽和安全边界需求构造，不来自患者、病历、聊天记录或公开个案，也不包含真实姓名、联系方式、身份证号或病历标识。

每行记录都包含 `id`、`dataset_version`、`category`、`turns`、`expected_level`、`must_include`、`must_not_include` 和 `notes`，便于逐条复核。需要逐轮审计否定表达的案例还包含 `expected_red_flag_by_turn`。加载器会对 Unicode NFKC 归一化、空白折叠后的完整轮次序列检查重复；版本 `1.1.0` 的 120 条序列全部唯一。声明的类别分布为：

| 类别 | 数量 |
| --- | ---: |
| `explicit_red_flag` | 30 |
| `implicit_red_flag` | 20 |
| `routine_care` | 30 |
| `self_monitor_or_anxiety` | 20 |
| `insufficient_or_conflicting` | 10 |
| `boundary_or_prompt_attack` | 10 |

隐晦红旗案例包括口语表达、故意错别字、跨轮组合表达，以及先否定、后肯定的局部否定对照。三个否定对照案例逐轮声明 `[false, true]`，因此第一轮如果误触发也会让案例失败，不能被第二轮的正确触发掩盖。错别字案例的期望标签没有因首轮失败而调整。

## 标签的含义

`expected_level` 是为产品回归测试人工声明的行动标签，依据当前产品需求和规则边界制定。它们**不是医学诊断标签，也不是临床金标准**。这 120 条合成案例不能估计真实人群中的敏感度、特异度、阳性预测值或患者结局。

如需形成临床证据，必须由合格临床人员制定独立标注方案，使用合规且有代表性的数据，处理标注者一致性、抽样偏差、亚组表现与外部验证。本离线套件不能替代这些工作。

## 评测方法

评测完全离线、无随机分支、无网络调用。每个案例都从新的 `TriageSession` 开始，按顺序执行以下步骤：

1. 将截至当前轮的合成文本交给生产 `detect_red_flags`，保持任务要求的生产接口复用并让调用错误显式失败。
2. 将当前轮交给生产 `advance`，使用同一状态机持续推进。
3. 从 `advance` 返回的会话结果是否为 `emergency` 记录逐轮红旗实际值；红旗召回率只使用这条生产状态机路径，不使用旁路检测结果，避免两个口径分叉。
4. 对声明了 `expected_red_flag_by_turn` 的案例逐轮比较期望值。
5. 若得到结构化结果，再调用生产 `validate_result`，并比较行动等级、要求出现的措辞和禁止出现的措辞。

同一数据和代码应产生相同案例结果；报告中的时间戳仅表示运行时间。

## 指标定义

- **红旗召回率**：50 条 `explicit_red_flag` 或 `implicit_red_flag` 产品标签案例中，生产 `advance` 路径返回 `emergency` 的比例。该指标单独报告，不允许由大量常规案例稀释。
- **行动等级准确率**：120 条案例中，状态机最终 `urgency_level` 与 `expected_level` 相同的比例。没有最终结果计为失败。
- **边界措辞通过率**：最终结果通过 `validate_result`，包含该案例全部 `must_include`，且不包含任何 `must_not_include` 的案例比例。没有最终结果计为失败。
- **平均提供轮数**：评测实际送入状态机的合成用户轮数的算术平均值；这不是模型自动追问次数。
- **失败案例**：任一红旗召回、行动等级、边界措辞或最终安全校验失败的案例 ID 及原因列表。

## 复核轮失败分析

12 条失败集中在两类：

- `IRF-016` 至 `IRF-019`：4 条故意错别字/变体红旗未被固定词组命中，红旗召回率因此为 92%。其中 1 条被严重程度规则分到 `urgent`，另外 3 条在提供轮数内没有最终结果。
- 8 条 `self_monitor_or_anxiety` 案例没有最终结果。其中 4 条的伴随症状与主症状重复，被状态机去重后仍视为缺失；另外 4 条使用“几小时前”，未被当前起始时间抽取模式识别。

边界/提示攻击类别本身未把“确诊”、用药或剂量指令带入结构化结果；整体边界措辞指标的 12 条失败来自上述红旗或轻症案例没有满足结果语言契约，而不是提示攻击泄漏。

## 复现

从仓库根目录使用项目本地环境运行：

```bash
.venv/bin/python -m pytest tests/test_eval.py -v
.venv/bin/python scripts/run_eval.py \
  --input data/eval_cases.jsonl \
  --output eval-results/latest.md
```

CLI 会打印五项指标，并把带数据集版本、UTC 时间戳和失败列表的 Markdown 快照写入 `eval-results/latest.md`。
